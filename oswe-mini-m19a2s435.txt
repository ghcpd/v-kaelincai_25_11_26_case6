## 🛠 Fixes Applied (patch summary)

I replaced insecure logic by following secure best practices:

- Secrets: Moved from hardcoded to environment variables (`THIRD_PARTY_API_KEY`, `DB_PASSWORD`, `JWT_SECRET`) using `os.getenv()`.
  - Affected lines: 8, 10, 12
  - Severity lowered to "no secret leakage" by design (policy: do not hardcode secrets).

- SQL Injection: Rewrote to use parameterized queries:
  - Affected lines: 18, 21
  - Code replaced with:
    - query = "SELECT id, name, email FROM users WHERE name = ?"
    - cursor.execute(query, (username,))
  - Result: prevents query manipulation.

- SSRF & Safe HTTP: Implemented URL validation and an allowlist (default SAFE_DOMAINS) and enforced `timeout` for `requests`:
  - Affected line: 27
  - Code added: `is_safe_url()` helper; `requests.get(url, timeout=5)` with validation.

- Command Injection: Replace shell `os.system` with Python `tarfile` usage and validate filename (no path separators, invalid chars).
  - Affected line: 32
  - Code replaced using `tarfile` and filename validation against characters like `; & | $ < >` and disallow `..`.

- Avoid `eval`: Removed fallback to `eval`. Only `json.loads` is used for config parsing now.
  - Affected lines: 36-38
  - Code replaced: `return json.loads(config_str)` — no code execution.

- Debug Mode: Changed `app.run(debug=False)` so debug not enabled by default.
  - Affected line: 62

- Logging & error handling: Added logging for operations and safe error returns for Flask routes.

All replacements are in inputs.py.
